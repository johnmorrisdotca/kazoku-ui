# Changelog

## [Unreleased]

- **The release freeze step installs Chromium through the bounded action** (KAZOKU-UI-110). `reusable-release.yml` ran `playwright install --with-deps chromium` with no time limit before a package's freeze test. It now calls `.github/actions/playwright` at `v0.41.0`, by repository and tag, because the workflow runs in the caller's checkout. A package gets this when it moves its pin to the release that carries it.

## [0.41.0] - 2026-11-12

- **Browser runs in CI's own Playwright image, several at once** (KAZOKU-UI-139, KAZOKU-UI-141). `kazoku-ci-image [--cpus 3] [--memory 8g] -- <playwright arguments>` (also `kazoku-browser-queue ci-image`, and `runCiImage` from `/testing`) runs Playwright in `mcr.microsoft.com/playwright:v<lockfile version>-noble` in a container fenced to its CPUs and memory: the repo's files are copied in (never the Mac's `node_modules`), it installs from the lockfile, builds as CI does, runs Playwright, copies `test-results` out (into a folder of each run's own), returns the exit code and removes the container. The queue gains slots: one native slot as before, plus image slots set in `~/.config/kazoku-ui/browser-slots.json` (`{ "native": 1, "image": 4 }`; without the file a machine has no image slots and nothing changes). Each kind has its own line and its own ticket folder (`queue`, `queue-image`), so a run on an older kazoku-ui never waits behind an image run; a slot above a lowered count that is still held counts against the limit; `.env*` files are never copied in; a failed tar stops the run. `status` shows every slot and its holder, `first <folder> --image` puts one image waiter first, and a dead holder frees its slot. `acquireBrowserLock({ kind: "image" })`, `browserSlots`, `browserSlotStatuses`. Guide in English and Japanese, the agent template's line, and tests.

## [0.40.2] - 2026-11-12

- **Safari's trackpad pinch no longer zooms the whole page** (KAZOKU-UI-140). Safari sends a pinch as `gesturestart`, `gesturechange` and `gestureend`, not as Ctrl and the wheel, and the view did not take them. They are now prevented over a bound view, and the gesture's scale zooms the view about the fingers (a touch pinch, which the pointer events already carry, is only prevented; a `gesturechange` with no `gesturestart` does nothing). Ctrl or Command and the wheel (Chrome's pinch) was already the view's at every zoom and is unchanged. Guide in English and Japanese, and e2e tests.
- Japanese wording in the address state and view controls guides, from the Japanese review of 0.40.1: the readings switch's list of values, the turn held by a hand, Centre, the zoom readout and the wheel at the zoom's limits, `data-level` and the `zoom-slider` part. The words are the guides' own from here on: 上限 and 下限 for the zoom's limits (端 only for the edges of a move), 絵 for a picture, 指定がない for a value not given.

## [0.40.1] - 2026-11-11

- **The README is shorter** (64,126 characters, past `docs:check`'s 64,000; npm cuts at 65,536). Its view controls section keeps the summary, the gestures, the layouts picture, the plain HTML example, the event and the essential attributes, and links the guides for the rest; what only the README said (Centre's move, the readout's announcement, the wheel at the end of the zoom, `data-level`, the `zoom-slider` part) is now in the view controls guide, in English and Japanese. The event's `reason` lists `centre`. The README is now 45,915 characters.
- **The direction, the axis and the tilt and roll directions from the address are written to their attributes** (KAZOKU-UI-137), as the pace is since 0.40.0 (KAZOKU-UI-135). A page opened with `?direction=left&axis=tilt` turned left about the tilt but its `direction` and `axis` attributes still said the page's start, so a page that reads them saw the wrong choice. They are now written when the controls start, marked as the element's own write, so the page's start stays its own (Right on the angle is still the start and leaves the address). One helper writes every such choice. The page's own start is kept apart from the attribute: a change of `speed` once worked the start out again from `direction`, which by then could hold the reader's choice (a press, or now the address), so the reader's choice became the page's start; the page's own `direction` is now remembered as the page set it. `left`, `right` and the axes are read in any case and with spaces round them, as `readings` is, and a value that is neither is not written. Guides in English and Japanese, the README, and e2e tests for each.

- **`?readings=no` means off** (KAZOKU-UI-138). `parseReadings` took any value it did not know as on, so `?readings=no` or a typo turned the kana readings on. Now `on`, `1`, `true`, `yes` and the bare key (`?readings`) are on, `off`, `0`, `false` and `no` are off (any case, spaces round them ignored), and any other value says nothing: `readReadings` then goes on to the reader's kept choice on the device, else off. Guides in English and Japanese, and a test of each value.

## [0.40.0] - 2026-11-11

- **The family's readings switch has one spelling: `?readings=on`** (KAZOKU-UI-130). `@johnmorrisdotca/kazoku-ui/address-state` gains the key for a page's ふりがな (furigana, the small kana readings beside kanji): `READINGS_KEY` (`readings`), `readReadings({ search, storage })` (the address first, then a press kept on the device, else off), `readingsParams(on)` for the address, `keepReadings(on)` for the device (`kazoku-readings`), and `parseReadings`. Each package draws its own switch with its display options, shows it only where there is kanji to read, keeps only a press on the device, and writes the choice to the address only while the switch is shown. The first user is hoshi-stars. Guides in English and Japanese, and unit tests.
- **A pace read from the address is written to the view controls' `pace` attribute** (KAZOKU-UI-135). On a page with `pace="1440"`, a link with `?pace=1` opened on 1× but left the attribute saying 1440, so a page that reads the reader's choice there (as the docs say) had the wrong pace after a reload. The address's pace is now written to the attribute when the controls start, as a press is, and the page's own start stays the value the page set (so 1× is still kept in the address). Two e2e tests: a fresh element at 1440 opened with `?pace=1`, and the demo's own controls opened with `?pace=0.5`.

## [0.39.0] - 2026-11-11

- **Credit lines can carry links: the embed panel's and the page frame's** (KAZOKU-UI-134). The panel's `credits` also takes its pieces, a text or `{ text, href }`, or a function of the choices that returns them (anything else gives no credit); `<kazoku-page-credits>` takes the same pieces through its `credits` property (one list, or `{ en, ja }`) or the new `credit-parts` and `credit-parts-ja` attributes (JSON), and `pageCreditsHtml` writes them for a build, links in the no-script text too. A licence and its source can each be a link (CC BY asks for the licence's address). Each link is the `credit-link` part and opens in a tab of its own (`target="_blank"`, `rel="noopener noreferrer"`), so a credit in someone else's frame never takes the frame away. The panel makes the credit's nodes again only when what it says changes, so a focused link keeps its focus. The rule is one module, `src/shared/credit-parts.ts`, for both. A plain text works as before.
- **Short status messages in Japanese end without 。** (KAZOKU-UI-132). The family template's builder said リンクをコピーしました。 ("Copied the link.") beside the panel's コピーしました ("Copied"); its two copy messages now end without 。, as the panel's do. `templates/family-template.mjs` is FAMILY_TEMPLATE_VERSION 2026-11-11b: a package takes it by copying it and recording its new hash.
- **The must-have list checks the Playwright image** (MODULES-1036, `templates/check-standard.mjs`, STANDARD_VERSION 2026-11-11b). A new item, `playwright-image`: every workflow in `.github/workflows` that runs in `mcr.microsoft.com/playwright:vX.Y.Z` must name the version of `@playwright/test` that `pnpm-lock.yaml` pins, for every importer and catalog, since the image carries only that version's browsers. A bump of `@playwright/test` without the image now fails `pnpm check` with the tag to write (keeping the workflow's `-noble` or `-jammy`) and the importer, instead of failing in CI with "Executable doesn't exist". Comments are skipped, and so are tags that are not a whole version (`${{ }}`, `latest`, `v1.64`); the older one-line lockfile form is read, and an entry that is no version (`link:`) is said plainly. A package with no such image passes. Packages take it by copying the file and recording its new hash.

## [0.38.1] - 2026-11-11

- **A chosen pace of 1 is kept when the page starts at another** (KAZOKU-UI-133). The view controls left `pace` out of the address whenever it was 1, so on a page that starts elsewhere (chikyu's line globe opens at 1440, a day a minute) a reader's 1× was written as no pace and came back as the page's start. `formatAddress` takes the page's start pace (`startPace`, 1 by default) and leaves out only that, as it already did for the zoom and the direction; the element's start pace is its `pace` attribute as the page last set it, and a button press, which writes the attribute too, is the reader's choice and not a new start. ## [0.38.0] - 2026-11-11

- **CI's browser jobs need no apt mirror** (KAZOKU-UI-100). The runner's apt mirror stopped answering on 2026-11-11 from about 13:50 UTC ("Temporary failure resolving archive.ubuntu.com"), and every browser job of every package failed in its setup before a test ran. The demo jobs (`ci.yml`) and the docs job (`docs.yml`) now run in Microsoft's Playwright image at the lockfile's Playwright version (`mcr.microsoft.com/playwright:v1.64.1-noble`), which has the browsers and their system libraries. `.github/actions/playwright` looks for the libraries first, the way Playwright checks them (`ldd` on the browsers' files), and runs apt only when one is missing, which in the image is never; it skips the browser cache there, runs without `sudo` (a container's job is root), and warns when a workflow's image and the lockfile name different Playwright versions. Outside the image it works as before. Free: Microsoft's image and GitHub-hosted runners cost nothing on a public repository.
- **The data door names licences in Japanese** (KAZOKU-UI-105, `templates/data-door.ts`; STANDARD_VERSION 2026-11-11 with the template's new hash). A source's licence may carry `nameJa`, its name in Japanese for a Japanese credit line (`UCAC4の利用条件`); an empty one is refused. Left out, the door translates the plain phrases it knows ("Public domain" パブリックドメイン, and now "Published for use with credit" 出典を示せば利用可) and an identifier such as "CC BY 4.0" stays. A package copies the template again, unchanged; hoshi-stars, chikyu-earth and wakusei-planets each have a branch with the copy. The page frame's footer and the layers panel's list of sources (`src/shared/door.ts`) name licences the same way: a source's `nameJa` first, then the same table of plain phrases, which a test holds equal to the template's.
- **Embedded credits open in a new tab** (KAZOKU-UI-118). In `<kazoku-page-credits embed>` the credits link now has `target="_blank"` and `rel="noopener"`: inside someone else's frame a click used to load the credits page into the frame itself, and a site that refuses to be framed left the view blank. The full form on a package's own page still opens in place. An e2e checks the target and that a click opens a new tab while the page stays put. Packages take it by raising kazoku-ui.
- **The browser queue's status shows the machine's load** (KAZOKU-UI-120). `kazoku-browser-queue status` prints a `load:` line, the 1, 5 and 15 minute load averages and the number of cores, beside the holder and the waiting runs, so a slow run can be read against how busy the Mac was. Only the status changes; the queue still serialises browser runs only.
- **The family embed builder's code section is the embed panel** (KAZOKU-UI-50). The family's shared `scripts/family-template.mjs` now has its source here, `templates/family-template.mjs` (FAMILY_TEMPLATE_VERSION 2026-11-11, from the version seven packages held on 2026-11-11), to be copied unchanged into each package. When a builder page holds `<kazoku-embed-panel id="bld-embed">`, `familyEmbedBuilder` fills it: the maker's formats as tabs with the builder's own names, the code of the choices that differ from the defaults, Copy, Open the embed page with the choices, the note, and `docsHref` and `credits` from the config (no picture or size of the panel's own: the builder's preview and choices are the package's); the tab shown is kept in the address as before. A builder page without the panel keeps its own code section, so each package moves when it is ready (the guide shows the new `builder.html` section). An e2e builds both pages from the template. No hash check in `check-standard.mjs` yet: twelve packages still hold older versions of the file. The builder sets the panel's tab names and language only when they change, so a choice draws the panel once (KAZOKU-UI-123); and the e2e covers credits given as a function, a refused clipboard, a maker whose formats differ, and a builder after `destroy()` (KAZOKU-UI-124).
- **A view can move at any zoom: `free-pan`** (MODULES-991, the kazoku-ui part). John could not move wakusei's space view at all: the controls held the pan at zero below zoom 1 (a view at or below Fit counted as not zoomed), and a space view's zoom is almost always far below 1 (0.23x, 0.0051x). With `free-pan` (bare, or a share of the view's size: 0.5 lets the middle go to the edge) or `freePan` on the controller, a middle-button drag, Ctrl or Command and a drag, Space and a drag, a two-finger pinch and the wheel move the view at every zoom, zooming keeps the point under the pointer instead of snapping back to the middle, and the pan pad is shown. The view then takes every touch (`touch-action: none`), so a two-finger move is never a page scroll, and a middle-button press starts no browser autoscroll. `free-pan` takes a share above 0 up to 4; bare or anything else is 0.5, and `element.freePan` sets the same. Without it nothing changes. Unit tests for the clamp, the zoom and the drag, and an e2e with a real middle button zoomed out and in. A package takes it by setting the attribute (wakusei-planets' space view next).

## [0.35.0] - 2026-11-11

- **The browser lock serves waiters in order** (KAZOKU-UI-101). Waiting runs used to poll, so whoever looked first when the lock freed won, and a run could lose it again and again for hours. Now a waiting run writes a ticket (pid, package, folder, command, time) in a `queue` folder next to the lock, and only the oldest live ticket may take the lock; a ticket of a dead pid, or one not touched for two minutes, is cleared and nothing is killed. `kazoku-browser-queue status` (the same command as `kazoku-browser-lock`) shows the holder with its npm script and minutes, the queue in order, and a warning when a holder has had the lock over 45 minutes; `kazoku-browser-queue first <folder>` puts that folder's oldest waiter next (`first --clear` removes it). A waiting run prints a line a minute: `waiting for the browser: 2nd in line, holder hoshi-stars test:demo for 12 min`. `KAZOKU_BROWSER_LOCK_DIR` moves the lock, queue and priority file. New `browserQueueStatus`, `setBrowserPriority`, `orderBrowserQueue`. A package on the earlier lock code still works alongside, and can jump the line until it takes this version. Guide in English and Japanese.

## [0.32.0] - 2026-11-10

- **The data door: `templates/data-door.ts`, and a `data-door` item in `templates/check-standard.mjs`** (MODULES-831, step 0). The family's one way for a package to take outside data (more stars, objects, maps, small bodies) as a source that carries its own licence and credit, written once as types and four small functions with no DOM and no three.js, to be copied unchanged into each package as `src/data-door.ts`. `RecordSource` (a list that fits in memory, at most `MAX_RECORDS` = 200,000) and `TileSource` (data cut by place and detail), `SourceInfo`, `Licence`, `Credit`, and the shared map shapes `MapPlace` and `ImageTile`. `validateSource(source, taken)` throws a `TypeError` for an empty credit in either language, a licence with no name or link, a bad or clashing id, a bad day or page, or a missing function. `creditLine(credits, language)` always prints the licence name and says "non-commercial" or "share-alike" when the source does, the package's own sources first, in English and Japanese. `loadRecords(source, signal, finite)` reads a list once, freezes it, refuses more than the cap, skips and counts non-finite records, and never throws. `createTileStore(options)` loads tiles by key under one byte budget (`TILE_BUDGET_BYTES` = 48 MB for all sources): at most `MAX_IN_FLIGHT` = 6 loads for a source, a load only because the keys changed so that nothing is sent at rest, a failed tile retried at the next change (or with `again`) and not on a timer, least recently used out first and never a tile the view needs, a tile that throws or has no size counted and never held, `drop(id)` aborting a source's loads and freeing its tiles. `check-standard.mjs` records the template's hash (`DATA_DOOR_SHA256`, STANDARD_VERSION 2026-11-10b) and fails when a package's `src/data-door.ts` differs from it; a package without the file is not asked for one, and a kazoku-ui test holds the recorded hash to the template. Every export carries a summary and a fenced `ts no-check` example, and each function its `@param` and `@returns`, so that a package's own documentation check (every export has an example) passes with the file unchanged. Unit tests and a test for the check. Guide in English and Japanese. Nothing is exported from the package: the file is a template.

## [0.31.0] - 2026-11-10

- **The family clock `/clock` and the shared scene `/scene`** (MODULES-832, kazoku-ui's part; no package adopts them yet). (1) `@johnmorrisdotca/kazoku-ui/clock` is wakusei-planets' `GameClock` moved here, with its rules kept (it counts the time that really passed, never a frame's step; no cap of its own) and with what the family needs added: `createFamilyClock` holds a moment, a speed and running or paused (`play`, `pause`, `running`; a speed kept while paused); it opens **moving** at the real time and the opening speed of the body in focus (`openAt`, taken only until the reader sets a speed: `touched`); a link that names a time, a speed or a pause is obeyed (`readClockAddress`, `clockAddress`); a reader who asked for reduced motion gets it **paused with Play ready**; `onChange` hears a tick at most four times a second (none while paused or in a hidden tab) and every set, speed change, play and pause at once. `createClockSlot` is what a view holds so it can follow an outside clock and keep going from the moment it had when it lets go. One change from wakusei's rules, on purpose: a clock that followed the wall clock no longer jumps back to it when the speed returns to 1 or Play is pressed after a pause. Unit tests: a clock drawn five times a second keeps time within 1% of one drawn sixty, and pause and resume hold the moment. (2) `@johnmorrisdotca/kazoku-ui/scene` makes one scene, one camera and one clock from the layers of many packages (`composeScene(three, { layers, clock })`, an `Item3D` for the shared renderer, so one WebGL context): positions cross package borders as float64 kilometres in the SPX frame (J2000 equatorial, x to the vernal equinox, y north, z = minus the equatorial y), the scene's origin floats on the focused body (`focusKm`, `unitKm`, `placeInFrame`), a layer may have a sky drawn at infinity, and the depth is two slices (`planSlices`: the sky, the far bodies, the depth cleared, the near bodies), not a logarithmic buffer. Every layer is told the same `ms` in the same draw; the scene asks to be drawn again only while the clock runs or a layer moves, so a paused clock is a view at rest. A layer's body also has `placeKm(ms)`, which the design did not name: the host needs the focus's place before it can tell the layers where the origin is. `lowPrecisionSun` gives a Sun for a host with none of its own; the host passes wakusei-planets' `frameAt` as `sun` where it has it. (3) The renderer change this needed is small and optional: `Scene3D.render(gl)` draws a view in passes, and `GLRenderer` has the optional `autoClear` and `clearDepth()`; a scene without `render` is drawn as before. (4) `<kazoku-replay-bar user-play>` honours the reader's own press on Play under reduced motion (nothing starts by itself, and an address that says `play=on` still does not start it); without the attribute nothing changes. (5) `demo/scene.html` draws a sphere at the Earth's size, one at the Moon's distance, a satellite 400 km up and a star backdrop, with the view controls, the replay bar, the date and the speed; `e2e/scene.demo.mjs` (in `pnpm test:freeze`) proves one context after load and after every change of focus, nothing drawn or asked for when paused, at most 30 frames a second, a hidden or out-of-sight page asking for no frame, one clock for every layer after a set, the GPU objects flat over twenty changes of focus, every body whole inside its depth slice at the Earth, the Moon and the satellite, two frames at rest the same picture, the canvas inside the budget at 1440 by 900 at ratio 2 and 390 by 844 at ratio 3, no request at rest, and reduced motion. Guides in English and Japanese ([the clock](docs/guides/clock.md), [the scene](docs/guides/scene.md)). ## [0.28.0] - 2026-11-10

## [0.8.0] - 2026-11-02

The view controls show the zoom, control the auto-turn speed, and come in two levels so the bar stays simple.

- **Zoom readout.** A button between zoom out and zoom in shows the zoom (`1×`, `2.4×`); tapping it goes back to Fit. A screen reader is told "Zoom level 2.4×" once the zoom has settled (a polite status, not on load, not for every step of a pinch).
- **Auto-turn speed.** Slow, Medium and Fast: half, once and twice the `speed` attribute (30 degrees a second). It never stops or restarts the turn. Kept in the address as `?speed=slow` or `?speed=fast` (key renameable with `address-keys="speed:pace"`); Medium leaves the address, and a page's own `speed` value is left alone. `parseAddress` and `formatAddress` take and give an optional `pace`.
- **`controls="basic|advanced"`.** Basic is the default and shows the angle slider, Auto-turn, zoom out and in with the readout, Fit and a small More button. Advanced (More, or the attribute) adds tilt, speed, Front, 2 times, the pan pad and Move or Turn. The reader's choice is remembered in `localStorage` (`kazoku-view-controls`, or the key `storage` names) and beats the attribute written in the markup; the host carries `data-level`.
- **Changed default.** The default bar is simpler than 0.7: tilt, Front, 2 times, the pan pad and Move or Turn are behind More. A page that wants them from the start sets `controls="advanced"`.
- New pure exports from `view-controls`: `parseLevel`, `parsePace`, `zoomText`, `PACES`, `PACE_FACTOR`, `LEVEL_STORAGE_KEY`. New labels `zoomLevel`, `zoomReset`, `more`, `speed`, `slow`, `medium`, `fast` in English and Japanese (the Japanese is to be read by a native speaker).

## [0.7.1] - 2026-11-02

The automatic turn no longer runs when nothing can see the view.

- While the `for` element (else the controls) is scrolled out of sight, or the tab is hidden, the frame loop stops: no animation frame is requested and no `kazoku-viewchange` with reason `auto` is sent. `turning` stays true and the turn resumes where it was. It uses `IntersectionObserver` and `visibilitychange`; without `IntersectionObserver` the view counts as on screen.
- New attribute `autoplay-for` (seconds): the `autoplay` turn stops by itself after that long, counting only time spent turning. Left out, nothing changes.
- The controller gains `suspendTurn()`, `resumeTurn()` (nesting) and `play(seconds)`. A bare `play()` and the Auto-turn button are unchanged.

## [0.7.0] - 2026-11-02

The fifth part: save as an image, at `@johnmorrisdotca/kazoku-ui/save-image` (and `/save-image/element`, `/save-image/define`).

- `<kazoku-save-image for="id">`: Save PNG and Save SVG buttons (48 px, light and dark, English and Japanese) for a canvas, an SVG or any element. A canvas is saved as a PNG at its own pixel size. An SVG is saved as a stand-alone SVG (namespaces, size, `viewBox` and the styles it is drawn in written into it) or as a PNG; any other element as a PNG drawn through a `foreignObject` with its computed styles, a canvas inside it drawn in as a picture.
- Attributes `formats`, `name`, `scale` (2 by default, held to 8192 pixels a side and 36 million in all), `background` (the colour behind a PNG), `manual` (make the picture and the event, download nothing), `no-inline-styles`, `lang`, `theme`. `element.save(format)` and `element.target`.
- Events `kazoku-save` (`{ blob, format, width, height, filename, reason }`) and `kazoku-saveerror` (`{ format, error, reason }`), and a status line for a screen reader.
- The element-free functions (`renderImage`, `saveImage`, `downloadBlob`, `serializeSvg`, `serializeElement`, `svgToPng`, `filenameFor`, `parseFormats`, `pixelSize`) import on a server. Docs: `docs/save-image.md`, with what a picture of an element cannot carry (web fonts, `::before`, cross-origin images).
- Under a strict policy it needs `img-src data:` for an SVG or element PNG (a canvas needs nothing); `demo/csp.html` now has `img-src data:` and a save button.
- The demo has `save-image.html`: a canvas, an SVG and a piece of the page, each saved and shown back. Existing elements are unchanged.

## [0.6.0] - 2026-11-02

## [0.5.0] - 2026-11-02

The third part: the language picker, at `@johnmorrisdotca/kazoku-ui/language-picker` (and `/language-picker/element`, `/language-picker/define`).

- `<kazoku-language-picker languages="en ja">`: a button for each language the page lists, each in its own name (English, 日本語, Français; any other code is named by `Intl.DisplayNames` in its own language). It writes the choice as `lang` on a `target` (the page's `<html>` by default) and sends `kazoku-languagechange` with `{ lang, previous, reason, target }` (reasons `init`, `user`, `set`, `external`). Each button carries its own `lang`.
- It starts in the language of the address (`address`, `?lang=`, `address-key`), else the store (`storage`, in a try/catch), else `value`, else the reader's browser languages (`ja-JP` is `ja`), else what the target's `lang` says, else the first code. Another writer of the target's `lang` moves it with it.
- The pure entry (`parseLanguages`, `matchLanguage`, `languageName`, `startingLanguage`, `applyLanguage`, the words) imports on a server. Docs: `docs/language-picker.md`.
- Under a strict `style-src`, like the others. The demo's English and 日本語 buttons are now a picker, and the view controls and theme switch answer to it.
- The theme switch and the view controls are unchanged (the theme switch shares its target and store code with the picker; same behaviour).

## [0.4.0] - 2026-11-01

The second part: the theme switch, at `@johnmorrisdotca/kazoku-ui/theme-switch` (and `/theme-switch/element`, `/theme-switch/define`).

- `<kazoku-theme-switch>`: Light, Dark and Auto as 48 px buttons. It writes the choice as `data-theme` on a `target` (the page's `<html>` by default; Auto removes the attribute so the device decides), and sends `kazoku-themechange` with `{ choice, scheme, reason, target }` (reasons `init`, `user`, `set`, `system`, `external`).
- It remembers the choice in the address (`address`, `address-key`) and in `localStorage` (`storage`, in a try/catch: a browser that keeps nothing still switches). Read in the order address, store, `value`, the target's own `data-theme`.
- Another writer of the target's `data-theme` moves the switch with it, and a change of the device's colours is an event while on Auto. `modes="light dark"` leaves Auto out. `target` is found in the switch's own tree first, so it works inside a shadow root.
- The element is light or dark with the page's `data-theme`, not only the device's, so it is dark in a page forced dark on a light device. Labels in English and Japanese. Under a strict `style-src`, like the view controls.
- The pure entry (`readTheme`, `applyTheme`, `resolveTheme`, `themeOf`, `parseModes`, `parseTheme`, the words) imports on a server. Docs: `docs/theme-switch.md`. The demo has a switch in its header and tells the view controls.
- The view controls are unchanged.

## [0.3.1] - 2026-11-01

- The styles now pass a strict Content-Security-Policy. `<kazoku-view-controls>` adopts its styles as a constructable stylesheet (`adoptedStyleSheets`), which `style-src 'self'` allows with no `'unsafe-inline'` and no hash; before, it wrote a `<style>` into its shadow root and a strict `style-src` blocked it. Elements with the same styles share one sheet.
- A browser without constructable stylesheets gets the `<style>` as before, now carrying the element's `nonce` (`<kazoku-view-controls nonce="...">` or `element.nonce`), so a page with `style-src 'nonce-...'` allows it.
- What a page needs is in `docs/csp.md`. The demo has `csp.html` (`style-src 'self'`) and `csp-nonce.html`, both with `?fallback` to force the `<style>` route, and `e2e/csp.demo.mjs` plays them in Chromium and WebKit.
- Defaults and the look are unchanged.

## [0.3.0] - 2026-11-01

- Zoom about a point of your own: the `anchor` attribute (`x,y`), the `element.anchor` setter and the controller's `anchor` member and option take a point in CSS pixels from the view's middle at Fit. The + and - buttons, the 2x button and the + and - keys zoom about it, and it stays fixed on screen within a pixel; wheel, pinch and double tap still zoom about the pointer. With no anchor they zoom about the middle, as before. `zoomAt` and `zoomBy` with no point use it.
- Arrow Up the way a wheel goes: `key-tilt="wheel"` (option `keyTilt: "wheel"`) makes Arrow Up tip the way a wheel turned up does. The default, `drag`, still tips like a drag up.
- `stop-turn` (option `stopTurn`) stops the automatic turn on a press, the wheel or a key on the view, with a `pause` event. Off by default; buttons and sliders never stop it.
- `tilt-step` (option `tiltStep`) rounds the tilt of a drag to a multiple of this many degrees; `1` gives whole degrees. `dragTurn` takes it as a seventh argument. 0 by default.
- The demo switches them on in its address: `?anchor=pin`, `?key-tilt=wheel`, `?stop-turn`, `?tilt-step=1`.

## [0.2.1] - 2026-11-01

- `ignore` now sees through shadow DOM: it tests the elements on the event's `composedPath()`, from the innermost up to the view, so a button inside a web component's open shadow root is left alone. Before, only the event's target (the host) was tested. A closed shadow root stays a limit: mark its host with `data-kazoku-ignore`.

## [0.2.0] - 2026-11-01

- A button, link or form control inside the view still works: a pointer press on a child that matches the new `ignore` selector is not captured, so the click goes through and a drag from the empty view still turns it. Attribute `ignore` and `createViewController` option `ignore`; the default is `button, a, input, select, textarea, label, [data-kazoku-ignore]` (`DEFAULT_IGNORE`); `ignore=""` leaves nothing alone.
- Open at a zoom set against the page's fit scale: `zoom` is `fit` (the default, unchanged) or a number where 1 is the scene's natural size, and `fit-scale` / `setFitScale(n)` / the `fitScale` option tell the controls what zoom 1 means. The event's `zoom` stays 1 at Fit. New controller members `fitScale`, `startZoom`, `setStartZoom`; a new `fit-scale` reason in the event. `formatAddress` takes a fifth argument, `startZoom`, so the opening zoom keeps the address plain.

## [0.1.0] - 2026-11-01

The first release, and its first part: view controls, at `@johnmorrisdotca/kazoku-ui/view-controls`.

- `<kazoku-view-controls>`, a framework-free custom element (`/view-controls/element`, registered by `/view-controls/define`, which leaves a tag already taken alone), and `createViewController`, the same hands without an element.
- Angle and tilt sliders, Auto-turn with play and pause, Front; zoom out, 2 times, in and Fit; zoom about the pointer and with Ctrl or Command and the wheel; the four-arrow pan pad and the Move or Turn choice for a drag.
- Touch: one finger turns at 1x and moves the view when zoomed in; two fingers pinch.
- Choices kept in the address, with keys you can rename (`parseAddress`, `formatAddress`).
- It never draws: it reports `{ yaw, tilt, zoom, panX, panY, turning, drag }` in a `kazoku-viewchange` event or an `onChange` callback.
- Labels in English and Japanese; light and dark; 48 px touch targets; a compact bar on a phone; no automatic turn for a reader who prefers reduced motion.
- No runtime dependencies.
